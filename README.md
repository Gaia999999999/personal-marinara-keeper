# Personal Marinara Keeper

**Current stable package: 4.1.11 — Lossless Checkpoint Storage.** Target: Marinara **2.5.0 / c565014**. This is a personal pilot; bounded campaign retention is not established.

Catalog: https://raw.githubusercontent.com/Gaia999999999/personal-marinara-keeper/main/catalog.json

Update the existing `personal-character-memory-v4-1` package through **Agents → Download Agents**. Fully stop and relaunch Marinara, refresh the browser, then open **Keeper Tracker Panel → Update setup → Apply v4.1.11 settings** while idle and refresh again. Keep one matching native Keeper. The model connection, sampling preferences and accepted chat memory remain in place. No separate agent JSON import is required. Installation alone does not rewrite a checkpoint.

4.1.11 uses a self-contained lossless checkpoint envelope to reduce repeated field names and repeated provenance text. Every fact, row identity, audience, exclusion, condition and historical provenance value remains available. The entire encoded envelope counts against **22,000 characters**, and decoded fields and rows retain their existing limits, including **36 ledger rows**. This recovers finite character headroom; it does not solve eventual row exhaustion. Already-lost facts require an explicit reviewed correction. See [LOSSLESS_CHECKPOINT_RELEASE.md](LOSSLESS_CHECKPOINT_RELEASE.md).

The release also adds narrowly defined admission checks for supported custody changes, objective observations and conditional plans. These checks reject certain omissions and unsupported replacements; they are lexical safeguards, not a general semantic validator. Negated, hypothetical and interrogative placement text cannot authorize the tested custody transitions. Conservative rejections remain possible for aliases, some NPC movement forms, carried-without-destination wording and contrastive destination clauses.

Atomic rejection, immutable accepted baselines, private audiences and exclusions, author-correction authority, unresolved-plan and quiet-cast protections, current evidence requirements and exact recovery anchors remain enforced. There is no automatic retry, partial save, silent eviction, cap inflation, model-authored retirement, semantic archive or seed replacement. Normal evidence uses eight prior messages; recovery examines at most 24 supplied entries. The 4.1.8 anchor/GM-wrapper compatibility repair is retained.

**Compatibility:** older Keeper releases cannot read the new packed checkpoint format. Back up the chat before updating. Once a packed checkpoint has saved, do not downgrade in that chat; keep the matching runtime or obtain a reviewed recovery procedure. The tracker badge is useful status, but verify the matching saved output and revision before advancing after a controlled test.

Stable 4.1.11 promotes the independently audited 4.1.11-rc.4 implementation unchanged apart from release/version/catalog/package metadata. Local verification passes **300 tests on source and 300 on the extracted native payload**, **27 packaging checks**, **106 promotion scope/integrity/syntax checks**, and the private replay/audit suites. These are offline checks; live model compliance and long-session capacity are not certified by them.

`source/` contains the runtime and generic regressions. Run `npm test` there; `python3 build.py` builds the native ZIP/catalog without uploading or installing. Older release documents and archives remain historical. Personal RP prose and World State are unchanged. Private chats, corrections and replay fixtures are not published here.
