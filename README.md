# Personal Marinara Keeper

**Current package: 4.1.4 — scene boundary repair.** Target: Marinara **2.5.0**, source reviewed at build **c565014**. Local regressions pass; the new prompt still needs a live model check. This is a personal pilot, not an official Marinara package or a campaign-readiness claim.

Catalog: https://raw.githubusercontent.com/Gaia999999999/personal-marinara-keeper/main/catalog.json

Update the existing `personal-character-memory-v4-1` package through Marinara's native catalog flow, fully restart Marinara, and refresh its browser page. In the Keeper Tracker Panel, expand **Update setup**, press **Apply v4.1.4 settings** while agents are idle, and refresh again. This restores the packaged prompt and evidence settings, including a 24-message supply pool. The selected model connection, sampling preferences and saved chat memory are retained. Use the existing Personal RP v4.1 preset; this is not a standalone agent JSON import.

The runtime now supplies a bounded, cleaned view of the accepted reply's ending beside the indexed evidence, with current author-source IDs and explicit source-precedence guidance. The prompt keeps unanswered choices and conditional next actions unresolved in coverage, scene, cast state and plans. Setup validation blocks explicitly enabled optional context, capabilities and tools. See [SCENE_BOUNDARY_REPAIR.md](SCENE_BOUNDARY_REPAIR.md).

The pinned host also repeats the assistant response in a separate block. Its tag stripping preserves enclosed GM-note text. The supported package API cannot suppress that block, so **4.1.4 does not remove it**. The repair makes the authoritative sources and scene ending explicit and tells the model to ignore conflicting unindexed annotations. This is model guidance, not a new semantic validator. Valid evidence IDs cannot prove that the model interpreted an action, audience or condition correctly.

Code carries omitted records and commits a complete validated checkpoint atomically. Automatic compaction permits only shorter whitespace-normalized text: it cannot change words or punctuation. Semantic changes require eligible current evidence; explicit corrections require current author evidence. Each change/access item permits 1–6 checked evidence IDs. Disclosure recipients exclude the sender, and multiple evidence-list failures are reported together. The earlier initialization repair is documented in [INITIALIZATION_REPAIR.md](INITIALIZATION_REPAIR.md), and the audit history in [AUDIT_REPAIR.md](AUDIT_REPAIR.md).

Normal evidence uses eight prior messages. Recovery can use up to 24 supplied messages, retaining all pending replies that fit. On the pinned host's manual retry route, the current assistant reply occupies one slot, leaving at most 23 prior messages after removal. Missing anchors block reconstruction rather than silently resetting memory. Author-notes seeds load only when no previous checkpoint is selected; they do not overwrite an existing save. Correct an already accepted semantic mistake through an explicit current author correction and a normal next update; do not use a historical rerun as an assumed in-place edit.

The panel reports the host's last recorded successful save and newer reply count. It does not certify the selected swipe or show the checkpoint revision. Inspect the checkpoint in the output/export for that; detailed errors remain in Agents. The panel makes no model calls, and its settings button writes only after a user click. Updating settings does not rewrite old checkpoints or relabel their original Keeper version.

Verification: **84 deterministic tests** (72 retained and 12 new), plus **20 packaging checks**. Five preservation/source/transaction modules are byte-identical to 4.1.3. The pinned host's response-builder functions also reproduce the GM-text issue offline. A private handcrafted next-turn correction passes against the actual saved baseline while retaining unrelated memory; it is not model output or a live save. No live model-compliance, browser-rendering, latency or token-cost claim is made. The next gate is a reviewed correction followed by three consecutive accepted story updates.

The checkpoint remains bounded at 22,000 characters and 36 ledger rows. Earlier state observations consume that capacity. Whitespace cleanup cannot provide long-session semantic compression; unique growth can exhaust the budget. There is no automatic archive or silent eviction. Inventory, injuries, combat, quests and large-campaign readiness remain outside this release.
